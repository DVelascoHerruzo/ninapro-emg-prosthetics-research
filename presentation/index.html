This project asks more than whether a model can name a gesture. It asks who it works for, why it predicts, and where it fails.

NinaPro supplies labeled movement recordings across intact and amputee cohorts. The long-term motivation is personalized prosthetic research, not a device produced here. CLINICAL AI / RAI FRAMEPERFORMANCE ≠ CLINICAL READINESS

A model can score well overall but make more errors for a particular group, exercise, or sensor setup. So accuracy alone cannot establish clinical usefulness.

Responsible AI asks who benefits, what evidence drives a prediction, when it fails, and whether a user or clinician can understand its limits. This project analyzes recordings offline; it does not control a prosthesis. We need to inspect the data and evaluation before interpreting any score.

KEY LIMIT“The model uses feature X” does not mean “feature X causes movement Y.”
CAUSAL CLAIMS REQUIRE DESIGNASSOCIATION ≠ INTERVENTION EVIDENCE

A predictive feature is associated with model output; it does not prove that the feature causes movement. Participant characteristics, exercise, handedness, and sensor placement can influence both signal and prediction.

The diagram highlights these potential confounders. Causal claims need a design that addresses them and defines an intervention. For now, test feature stability across participants and alternative explanations. Importance is evidence about the model, not automatically physiology.

11 / MITIGATIONS

FROM RISK TO CONTROL

Five controls before
clinical consideration.

01Validate across peopleLeave-one-subject-out or held-out participants; never rely only on random windows.CHECK: zero overlap of participant IDs across train/test.
02Report subgroup evidenceAccuracy, sensitivity, specificity, F1, calibration, and per-person confusion.CHECK: review worst-performing group and participant.
03Keep uncertainty visibleAdd “uncertain / no action” and validate confidence thresholds.CHECK: quantify false activations and missed intentions.
04Personalize with guardrailsGeneral model → short calibration → user-specific test.CHECK: calibration data never reused for final evaluation.
05Keep human controlUser override, clinician oversight, logging, drift alarms, rollback.CHECK: define stop criteria before a pilot.
MITIGATION PLAYBOOKMODEL SUPPORTS · DOES NOT REPLACE CLINICAL JUDGMENT

Before clinical consideration, validate on unseen participants, report subgroup metrics, and let the model abstain when uncertain. Keep calibration sessions separate from final testing and preserve user override.

Define monitoring and stop rules before a pilot. Watch cohort errors, signal quality, sensor displacement, and drift. These are safeguards for future studies, not evidence of current readiness.

GOVERNANCE / PRIVACY / SAFETYPROS, CONS, CONSEQUENCES

Potential benefits include personalization, faster recognition, and simpler hardware. Risks include group disparities, unintended actions, information loss, drift, and privacy concerns.

Governance should require population documentation, subgroup reporting, privacy protection, clinical validation, monitoring, and failure procedures. A benchmark score alone is not clinical readiness; users and clinicians must be able to recognize the system's limits.
